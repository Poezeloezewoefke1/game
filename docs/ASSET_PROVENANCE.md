# Asset provenance

Every byte of art in this repository is generated by code that also lives in
this repository. Nothing was downloaded, nothing is licensed from a third party,
and there is no attribution obligation attached to shipping, modifying or
relicensing any of it.

That is worth stating explicitly, because the obvious alternative was tried
first and rejected on the evidence below.

## What was attempted, and why it was not used

The owner authorised downloading online models and photographs of planets. Two
things stopped it:

**The network.** Outbound HTTPS from the build environment goes through a proxy
with a narrow allowlist. Reachability was measured, not assumed:

| Host | Result |
| --- | --- |
| `raw.githubusercontent.com` | reachable (binaries included) |
| `registry.npmjs.org` | reachable |
| `pypi.org`, `files.pythonhosted.org` | reachable |
| `api.github.com` | reachable, but gated to this session's own repository |
| `images-assets.nasa.gov`, `photojournal.jpl.nasa.gov`, `svs.gsfc.nasa.gov` | **403 at the proxy** |
| `upload.wikimedia.org` | **403 at the proxy** |
| `api.polyhaven.com` | **403 at the proxy** |
| `www.solarsystemscope.com` | **403 at the proxy** |
| `cdn.jsdelivr.net`, `github.com/*/raw/*`, `codeload.github.com` | **403 at the proxy** |

Every primary source of public-domain or CC0 imagery is blocked. NASA's own
`nasa/NASA-3D-Resources` repository states the right terms - "These assets are
free and without copyright" - but its file listing is only available through the
GitHub API, which is scoped to this project's repository, and blind path
guessing through a directory tree did not find the maps.

**The licences on what IS reachable.** Planet textures do exist on
`raw.githubusercontent.com`, and they were fetched and inspected:

* `mrdoob/three.js` `examples/textures/planets/` - reachable, but the directory
  carries no licence statement of its own and the repository's MIT licence
  covers the library rather than third-party example assets.
* `jeromeetienne/threex.planets` - the README says the images come from
  planetpixelemporium, whose terms do not permit redistribution. The repository
  calls itself MIT, but an author cannot relicense someone else's textures.

Committing either would have put a licensing problem into a public repository.
It was not done.

## What is here instead

| Asset | Produced by | Notes |
| --- | --- | --- |
| `assets/textures/*.png` | `tools/generate_textures.gd` | Seamless PBR sets for rock, sand, hull, moss, plus a shared detail normal. Re-runnable; the script is the source, the PNGs are build output that is committed so a clone can run without a generation step. |
| Every model in the game | `scripts/utility/mesh_factory.gd` and its builders | Characters, weapon, enemy, props and set dressing, assembled from generated primitives. |
| The sky, planets, stars and galaxy | `shaders/deep_space_sky.gdshader` | Analytic, not photographic - see below. |
| Crystal, hologram and energy-field looks | `shaders/*.gdshader` | |

## Dropping real photographs in later

The sky shader was written so photography can replace the generated planets
without touching anything else. Each body has an `albedo` texture slot and a
`use_photo` flag:

```
planet1_photo      : sampler2D   equirectangular map, any resolution
planet1_use_photo  : bool        false = generated surface, true = the texture
```

Assign an equirectangular planetary map to the slot, set the flag, and the same
sphere intersection, terminator, limb darkening, atmospheric rim and ring shadow
are applied on top of it. Nothing else changes. If you supply files, put them in
`assets/textures/planets/` and record their source and licence in this document.

Suitable public-domain sources, when a machine can reach them:

* NASA Scientific Visualization Studio, `svs.gsfc.nasa.gov`
* NASA/JPL Photojournal, `photojournal.jpl.nasa.gov`
* USGS Astrogeology map catalogue

NASA material is public domain; the standard condition is that it must not be
used to imply NASA's endorsement.
